# Стек: Swift-пакет (SPM, сервер/библиотеки)

Конвенции для ролей, работающих со Swift-пакетом (server-dev, qa, reviewer).
Канон — `dev-process/stacks/swift-package.md`; копия в проекте —
`docs/stack/swift-package.md`.

## Сборка и тесты

- `swift build` и `swift test` — форграундом, с явным timeout; зелёный
  `swift test` локально — до завершения задачи, не «должно пройти».
- Тесты — swift-testing (`@Suite`/`@Test`): быстрые, детерминированные,
  без сети — внешний транспорт мокается на границе своего клиентского слоя.
- Тёплый кэш: если в проекте есть `scripts/warm-worktree.sh` — в новом
  worktree первым делом `scripts/warm-worktree.sh attach <путь-worktree>`;
  между стадиями `build-for-testing` → `test-without-building`.
- Сборок ≤2 одновременно (CPU делится с CI на той же машине).

## База данных в тестах

Поднял тест-БД в worktree (`docker compose up`) — перед финальным отчётом
погаси её там же: `docker compose down`. Имя compose-проекта берётся из имени
каталога worktree, поэтому каждый агент плодит СВОЙ контейнер, и за собой его
никто, кроме тебя, не уберёт (хвосты снимает только чеклист границы спринта).
Основную БД проекта (не из твоего worktree) не трогай.

## Данные и секреты

- Миграции — только аддитивные; разрушающее изменение схемы — не твоё
  решение: явное согласование через manager'а/оркестратора.
- Секреты только из окружения; в коде, репозитории и тестах секретов нет.

## Строгая конкурентность

Swift 6 strict concurrency: новые `@unchecked Sendable`,
`nonisolated(unsafe)`, `@preconcurrency` — только с обоснованием в
комментарии; без обоснования это находка ревью.
