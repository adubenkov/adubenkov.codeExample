# AGENTS.md — карта проекта для агентов (шаблон посева)

> Посеян `process-init` (аудит №4: самый цитируемый ролями документ отсутствовал
> в каноне — 12 упоминаний в шести ролях вели в пустоту). Замени заглушки
> `<...>` на своё; структуру и «Гигиену shell-команд» сохраняй — на них
> ссылаются роли.

Проект: публичная витрина Swift/iOS-примеров для найма — продакшен-паттерны,
тесты, инженерные стандарты; расширение резюме владельца.
Стек: Swift / SPM, GitHub Actions; роль разработки: `ios-dev`.


> Общие правила работы агентов — вход работы, гигиена shell-команд, скратчпад
> порции, синхронные прогоны, экономия токенов — в `docs/process/RULES.md`
> (копия канона). Здесь только проектное: карта доков, зоны, риск-триггеры,
> скиллы.

## Карта доков (прочти нужное ДО работы, не вместо неё)

| Документ | Что там |
|---|---|
| docs/TEAM.md | регламент конвейера (копия канона dev-process) |
| docs/STATUS.md | что происходит сейчас — ведёт manager |
| docs/specs/BACKLOG.md | **вход работы**: идеи, chore-очередь, побочные находки, CONFLICT |
| docs/stack/*.md | конвенции сборки/тестов/сервисов твоего стека |
| docs/CodeStyle.md, docs/Evolution.md | стандарты и эволюция витрины |
| docs/InterviewWalkthrough.md | как витрину читает нанимающий — держи её такой |

Второй трекер (GitHub Issues, чужой скилл-пак) — опционален и вход работы НЕ
заменяет: если он в проекте есть, назови здесь одной строкой, что осталось
жить в нём и почему, а его собственный документ обязан сослаться на
`docs/specs/BACKLOG.md` (правило — в шапке того файла; расхождение ловит
`process-doctor`).

## Зоны ролей

Каталоги, которыми владеет каждая пишущая роль (дифф PR обязан соответствовать
зоне автора; на эту таблицу ссылаются роли канона):

| Роль | Каталоги зоны |
|---|---|
| `ios-dev` | `examples/`, `scripts/`; `legacy/` — только чтение |
| devops | `.github/workflows/` |

## Риск-триггеры (повышают категорию PR до «рисковый»)

Семантические триггеры, которых не видит таблица путей (`docs/process/pr-category.tsv`);
manager применяет их суждением — только вверх:

- публичность: внутренние имена, чужой код без лицензии, любые секреты = BLOCK
- изменения в `legacy/` (исторический слой, трогается отдельным решением)
- переименование/перенос примеров (ломает внешние ссылки из резюме)
- CI-воркфлоу (бейдж в README — витрина зелёности)

## Скиллы (вызываются ДО работы, front-load в постановке)

| Зона | Скиллы |
|---|---|
| пишешь или меняешь тест; ревью диффа с тестами | `test-audit` — фильтр для нового теста, мусорные образцы, тестовые швы в продукте |
| чистка тестов (аудит, кампания) | `test-audit` — роль с `Edit` и прогоном тестов |
